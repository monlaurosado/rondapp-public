# Build and Internal Testing

## Local checks

```bash
npm run typecheck
npm run lint
npx expo-doctor
```

## EAS setup

Project linked to `@rdrosado/rondapp`. Verify the active account and project:

```bash
npx eas-cli whoami
npx eas-cli project:info
```

The EAS project ID has a public fallback in `app.config.ts`. Supabase client variables are configured in the EAS `development`, `preview`, and `production` environments.

## Android preview APK

```bash
npm run build:android:preview
```

The `preview` profile builds an APK for internal distribution:

```json
{
  "distribution": "internal",
  "android": {
    "buildType": "apk"
  }
}
```

Share the EAS install URL with testers. Android may ask them to allow installing unknown apps from the browser or messaging app used to open the link.

## OTA updates for installed builds

Preview builds use the `preview` channel and `runtimeVersion` follows the app version. For JavaScript, styles, copy, and assets that do not change native dependencies:

```bash
npm run update:preview -- --message "Describe el cambio"
```

Changes to native packages, permissions, plugins, bundle identifiers, or `app.config.ts` require a new build. Production updates use `npm run update:production`.

## iOS preview / Ad Hoc

Requires Apple Developer Program.

```bash
npx eas-cli device:create
npm run build:ios:preview
```

For Ad Hoc/internal distribution, each tester iPhone UDID must be registered before the build. Adding a new iPhone later requires a new build.

## TestFlight path

For broader iPhone testing:

```bash
npx eas-cli build -p ios --profile production
npx eas-cli submit -p ios --latest
```

Create the app in App Store Connect and invite testers through TestFlight.

## Push notifications

Push tokens are registered and unregistered through authenticated RPCs. Real push delivery
should be tested in a native EAS build, not only Expo Go.

Verify:

- iOS/Android permission prompt appears.
- `device_tokens` row is created by `register_device_token` and removed on logout.
- Creating a round invokes `send-round-notification`.
- Creator does not receive their own round notification.
- Muted group members do not receive notification.
- A repeated invocation for the same round returns duplicate/no-op and does not resend.
- Tapping notification opens `rondapp://round/{roundId}` equivalent route.

## Known credential blockers

These cannot be generated by the codebase:

- Supabase project URL and publishable key
- Supabase service role key for Edge Functions
- Apple Developer account and iOS devices
- APNs/FCM credentials managed through EAS

The app remains runnable without credentials and shows a configuration screen if Supabase client variables are missing.
